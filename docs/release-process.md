# Release process

A release is a COPR build of one package from `main`.

## Versions

| package | Version | Release | bump when |
|---|---|---|---|
| kernel | the Linux version of the pinned Asahi commit (`7.2.11`) | `<N>.asahiwip.plus<M>` (`900.asahiwip.plus1`) | by hand in `packages/kernel/kernel-plus.conf`: `N` (`PKGRELEASE`) for a newer Asahi commit on the same Linux version, `M` (`BUILDID`) for our patches, configs or packaging only (README.md, Kernel release naming) |
| apple-avd | `<kernel version>.<n>` (`7.2.11.1`) | `1`, `2`, ... | Version for a rebase or a new patch set; Release for packaging-only changes |
| apple-ave | `0.99.<n>` | `1`, `2`, ... | Version for a new upstream commit; Release for packaging-only changes |
| mesa-honeykrisp-plus | Fedora's Mesa version | `1`, `2`, ... | Version with Fedora; Release for a patch change |
| qemu-vmapple | `<QEMU VERSION>^<date>git<QEMU commit>` (up to `^20261011git51c70eb`: the Reims commit) | `1`, `2`, ... | Version for a new QEMU commit; Release for packaging-only changes |
| reims-vgpu-backend | `<crate version>^<date>git<Reims commit>` | `1`, `2`, ... | Version for a new Reims commit; Release for packaging-only changes |

Every change to a spec gets a `%changelog` entry:

```
* Sat Oct 10 2026 aquarat <3090997+aquarat@users.noreply.github.com> - <version>-<release>
- what changed
```

The kernel's changelog entry is generated by `scripts/make-srpm.sh`.

## Steps

1. Make the change on a branch; update the spec, changelog and docs.
2. `scripts/build-srpms.sh <package>` (and `PREP_CHECK=1` for the kernel).
   For a functional change, build the binary RPMs on a Fedora aarch64 machine
   (`dnf builddep` + `rpmbuild --rebuild`) and test them.
3. Push; open a pull request; wait for `ci` to pass.
4. Merge to `main`.
5. Actions > `copr-build` > Run workflow > the package (or `copr-cli
   build-package aquarat/apple-silicon-kernel-plus --name <package>`).
6. When COPR has published the build, install it on a test machine from the
   COPR repository and check it: for the kernel, boot it and run the checks
   in [kvm-macos-guests.md](kvm-macos-guests.md), Thunderbolt and the
   10GbE port (packages/kernel/README.md); for the DKMS packages,
   `dkms status`; for Mesa, `honeykrisp-plus vulkaninfo --summary`; for
   QEMU and the GPU backend, boot a guest with the GPU.
7. Tag the commit: `<package>-<version>-<release>`, for example
   `apple-avd-7.2.11.1-1` or `kernel-7.2.11-900.asahiwip.plus1`.

## Commits

- One logical change per commit, plain messages.
- No hostnames, IP addresses, personal paths or e-mail addresses other than
  the GitHub noreply address.
- Never commit Apple firmware, IPSWs, keys, tokens or generated tarballs;
  `.gitignore` blocks the usual names.
